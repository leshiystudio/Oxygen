# Oxygen на Linux-сервере (Docker)

Сервер `sct.Server` — мир без окна: симуляция идет на полной скорости и ничего не рисует,
пока никто не смотрит.

Кадры — по часам сервера. Время делится на отрезки по `--frame-ms` (по умолчанию 1000 мс);
кадр каждого слоя (режим ботов + фон + размер клетки) рисуется только когда его кто-то
запросил и не больше раза за отрезок — сколько бы зрителей ни смотрели и как бы часто ни
спрашивали. Частоту выбирает не зритель, а сервер (аргумент или порт управления). Зритель
получает шаг и время кадра и момент следующего и приходит ровно тогда; кадр, который у него
уже есть, сервер не шлет (`304`). Мир на паузе — кадры не перерисовываются.
Итого нагрузка на рендер — не больше «число разных слоев × 1000 / frame_ms» кадров в секунду
(проверено: 280 запросов/с от 15 зрителей на 3 слоях — 3 рендера/с при кадре раз в секунду).

**Доставка кадров — потоком.** Страница открывает `/stream` — один долгий ответ
`multipart/x-mixed-replace`, в который сервер сам кладет новый кадр слоя в начале каждого отрезка
(без опроса; на паузе — тишина). Кадр берется из того же кеша, так что рендер не зависит от числа
потоков. Не получилось (лимит потоков, прокси копит ответ) — страница сама переходит на опрос
`/frame.png` и через минуту пробует поток снова; что сейчас — видно в строке *frame* (`stream` / `polling`).
Поток можно смотреть и без страницы: `<img src="http://<сервер>/stream?mode=0&bg=1">`.

**Размер клетки 1–2 px — один кадр.** При 1 и 2 px линии направления нет и семечко занимает всю клетку,
поэтому сервер рисует и шлет 1 px на клетку, а растягивает браузер: вчетверо меньше пикселей
(200 x 200: 14 КБ вместо ~55 КБ). 3 и 5 px — с направлениями, как в программе.

**Лимит запросов зрителя.** На порту просмотра каждый адрес — не больше `--view-rps` запросов в секунду
(по умолчанию 10, всплеск `--view-burst` 30), сверх — `429`; потоков с адреса — не больше
`--streams-per-ip` (6), всего — `--max-streams` (500). Обычной странице хватает с запасом (поток + статус
раз в секунду + графики раз в 3 с). Меняется на порту управления (*view 10 req/s*); порт управления не
ограничен. За обратным прокси все зрители — один адрес: тогда лимит ставят на прокси
(`limit_req`, `limit_conn` в nginx), а у сервера поднимают или выключают (`--view-rps 0`); для потока в
nginx нужно `proxy_buffering off` (сервер шлет и `X-Accel-Buffering: no`).

| Порт в контейнере | На хосте (по умолчанию) | Что там |
|---|---|---|
| 8080 | `80`, для всех | **Просмотр, только чтение**: мир (режимы ботов и фона и масштаб выбираются у зрителя и на мир не влияют), численность популяций, графики, CSV истории |
| 8081 | `127.0.0.1:8081`, только с сервера | **Управление**: пауза, шаг, скорость, Again, новый мир по настройкам, сохранение и загрузка миров |

Вверху обеих страниц — когда запущен текущий мир и сколько реального времени он идет
(`started 2026-10-20 17:39:13 · running 1 y 2 mo 04 d 14:21:49`; месяцы — по календарю, годы —
когда наберутся). Отсчет — с создания мира
(New world, Again); время хранится в файле мира, поэтому после перезапуска контейнера
(`--resume`) и загрузки `.oxw` счет продолжается, а не начинается заново. Время на паузе входит.

## Перезапуск при вымирании, принудительный перезапуск и перенос лучших

На вкладке *World & species* (в программе, в веб-управлении) или параметрами `--set`:

| Параметр | Смысл |
|---|---|
| `restart_mode` = `off` / `all` / `any` | перезапуск, когда вымерли все популяции / любая популяция (семечко бота — живое, труп растения — нет). Те же настройки, зерно — следующее, иначе мир повторится |
| `restart_forced` = `0` / `1` | принудительный перезапуск — и без вымирания: через `restart_steps` шагов текущей попытки (счет с нуля после каждого перезапуска). Перенос лучших — как при вымирании (живые тоже попадают в оценку). Работает и при `restart_mode=off` |
| `restart_steps` | через сколько шагов попытки принудительный перезапуск (по умолчанию 100000, не меньше 1) |
| `elite` = `0` / `1` | при перезапуске каждая популяция заполняется **точными клонами** лучших за серию — по кругу: при 3000 стартовых и 100 лучших — по 30 копий каждого |
| `elite_size` | сколько лучших хранить на популяцию (по умолчанию 100) |
| `elite_fields` | по каким счетчикам оценка: `lifetime` (ходов прожил), `children` (потомков), `energy` (энергии добыл из мира: солнце, органика, почва, CO2, еда), `kills` (съел существ), `generation` (глубина рода) |

Оценка — сумма выбранных полей, каждое поделено на свое среднее по смертям популяции (поля разного масштаба
весят одинаково), по убыванию. Существо оценивается в момент смерти, когда жизнь закончена: на каждом шаге
ничего не перебирается, на смерть — несколько сложений и одно сравнение с худшим в архиве; наследственность
(геном, веса нейросети) копируется только у попавших в архив. Подходит любому виду и мозгу. Замер: 4,0 против
4,1 мс/шаг с включенным архивом. Архив копится за всю серию; New world и Again начинают новую серию.

Вверху страниц — `restarts N · this try …` (перезапусков и время текущей попытки), `started` — начало серии.
Число перезапусков и начало серии хранятся в файле мира; архив лучших — нет (после загрузки набирается заново).
Растение оценивается по клетке (у biosim каждая клетка — отдельное существо со своим геномом).

## Видео за последний час

`--record 0_2,8_0` в `OXYGEN_ARGS` — сервер пишет эти виды (номер режима ботов `_` номер фона, как в списках
страницы, с 0: `0_2` — predators на org+oxygen, `8_0` — kin без фона). На странице просмотра появляется блок
*Last hour (video)*: выбрать вид, *Play* — видео за последний час с перемоткой, вверху плеера — реальное время куска.

Как устроено (план и замеры — [video-plan.md](video-plan.md)): раз в секунду вид рисуется в 1 px под блокировкой
мира, сырые пиксели уходят в ffmpeg, тот пишет HLS — сегмент на минуту, в плейлисте 60 сегментов, старые удаляет
сам. Ничего не пересобирается. На паузе кадры не пишутся; новый мир того же размера пишется без шва (видно и
вымирание, и перезапуск); ffmpeg упал — перезапуск через 5 с, окно продолжается с разрывом; после перезапуска
контейнера — тоже (том `video`).

| Замер (мир 400x400, два вида) | |
|---|---|
| скорость симуляции | 6815 шагов за 140 с против 6828 без записи — **−0,2 %** |
| ffmpeg | 3–4 % одного ядра на вид |
| час записи | 150–300 МБ на вид: кадры раз в секунду почти не похожи друг на друга и сжимаются плохо |
| просмотр | 10–20 Мбит/с при 30 кадрах/с — для туннеля много: `--record-fps 15` вдвое меньше (час — 4 мин видео), `--record-crf 32` — еще меньше ценой четкости, `--record-ms 2000` — вдвое меньше и файл |
| задержка | свежая минута появляется в плейлисте через ~1,5 мин (кодировщик копит кадры) |

**По шагам** (`--record-steps 50`) кадр снимается в потоке симуляции в конце каждого 50-го шага: в видео — ровно
шаги 50, 100, 150…, скорость мира на запись не влияет (секунда видео — всегда `N × fps` шагов). Цена та же — рендер
4–7 мс на кадр, но теперь она зависит от частоты: при шаге 10 мс кадр каждые 50 шагов — ~1 % скорости на вид,
каждые 10 — ~5 %, каждый шаг — +40…70 %. Окно — шаги, а не минуты: сегмент — 60 кадров, в плейлисте столько
сегментов, чтобы покрыть `--record-window-steps`. На странице вместо «1 мин мира = …» — «1 с видео = N шагов».

Сегменты отдает тот же порт просмотра (`/video/<вид>/index.m3u8`), и на них действует лимит запросов
`--view-rps`; плеер — `hls.js` из `src/sct/web` (Safari — свой). Без ffmpeg в системе запись выключается
(строка в логе, `state: missing` в статусе), сервер работает как раньше.

## Мозг существа по координатам

В просмотре: щелчок по миру выбирает клетку (или ввести x, y), *Get brain* — сервер возвращает
снимок мозга существа в этой клетке, и он показывается по своему типу, как в окне генома программы:
геном команд бота (сетка 8 x 8 на геном, цвет — категория, рамка — текущая команда), геном растения
think_new (32 гена x 23 команды, рамка — активный ген) или think_old (линейная программа), веса
нейросети (тепловая карта по слоям). Наведение на ячейку — расшифровка. Снимок не меняется, пока не
запросить снова. *Copy* и *Save .json* — снимок целиком (в буфер обмена или файлом
`brain_<x>_<y>_step<N>.json`). Ссылка на клетку: `http://<сервер>/#brain=10,10`.

Частоту ограничивает сервер: один зритель (адрес) — не чаще раза в `--brain-limit` секунд,
по умолчанию 10; меняется на порту управления (*brain 1 / 10 s*, 0 — без ограничения). Запрос пустой
клетки не засчитывается, порт управления не ограничен. Если перед сервером стоит обратный прокси,
все зрители для сервера — один адрес, и ограничение становится общим.

## Запуск через CloudPub (основной вариант)

Туннель [CloudPub](https://cloudpub.ru) публикует просмотр по постоянному адресу `https://….cloudpub.ru`:
порты хоста наружу не открываются, HTTPS дает туннель. В `docker-compose.yml` это сервис `cloudpub`
— обычный, без профиля, как прод-туннель SW.APP: поднимается любым `docker compose up -d` и после
перезагрузки хоста; `.env.example` уже настроен на этот вариант.

```bash
git clone … && cd Oxygen
cp .env.example .env          # CLOUDPUB_TOKEN — из личного кабинета CloudPub; OXYGEN_CONTROL_TOKEN
docker compose up -d --build  # поднимет oxygen и cloudpub
docker compose logs cloudpub  # публичный адрес; он же — в личном кабинете
```

- **Что публикуется** — `CLOUDPUB_HTTP`: по умолчанию `oxygen:8080` (только просмотр).
  `oxygen:8080,oxygen:8081` — и управление, отдельным адресом; тогда `OXYGEN_CONTROL_TOKEN` обязателен
  (длинный случайный: `openssl rand -hex 24`). Basic auth самого CloudPub (`--auth basic`) на управление
  не ставить: он занимает тот же заголовок `Authorization`, что и токен управления.
- **Адрес не меняется** между перезапусками, пока жив том `oxygen_cloudpub-config` (там агент CloudPub).
  Имена томов (`oxygen_worlds`, `oxygen_video`, `oxygen_cloudpub-config`) закреплены в `docker-compose.yml` и не
  зависят от имени каталога проекта. Не удалять их: `docker compose down -v` стирает агента (новый адрес) и сохранения.
  Проверить агента и публикации: `docker compose exec cloudpub /clo ls`.
- **Порты на хосте** — только `127.0.0.1` (`OXYGEN_VIEW_PORT=8090`, `8081`): с самого сервера и через SSH.
  Так туннель — единственная дорога снаружи.
- **Адрес зрителя.** За туннелем все запросы приходят от контейнера CloudPub, и лимиты «по адресу» стали бы
  общими на всех. `OXYGEN_TRUST_PROXY=1` (в `.env.example` включен): для соединений из внутренней сети
  адрес зрителя берется из `X-Forwarded-For` (самый правый публичный адрес) или `X-Real-IP`. После запуска
  откройте `https://<адрес туннеля>/api/whoami`: в `client` должен быть ваш внешний адрес. Если там
  внутренний адрес — CloudPub заголовки не передает; тогда лимиты общие, и их стоит поднять
  (`--view-rps 50 --brain-limit 2` в `OXYGEN_ARGS`).
- **Поток кадров** через туннель: если туннель копит ответ, страница через 8 с сама перейдет на опрос
  (в строке *frame* будет `polling`) — смотреть можно и так.

## Запуск без туннеля

```bash
cp .env.example .env          # OXYGEN_VIEW_BIND=0.0.0.0, OXYGEN_VIEW_PORT=80, OXYGEN_TRUST_PROXY=0
docker compose up -d --build oxygen     # только oxygen: без токена CloudPub туннель перезапускался бы по кругу
```

Просмотр — `http://<сервер>/`. Управление по умолчанию снаружи недоступно — через SSH-туннель:

```bash
ssh -L 8081:localhost:8081 user@server     # затем http://localhost:8081/ на своем компьютере
```

Чтобы открыть управление наружу — `OXYGEN_CONTROL_BIND=0.0.0.0` в `.env`, и тогда токен
обязателен (Basic auth: логин любой, пароль — токен; трафик не шифруется — для интернета
лучше туннель или обратный прокси с HTTPS).

## Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OXYGEN_CONTROL_TOKEN` | пусто | пароль порта управления; пусто — без пароля |
| `CLOUDPUB_TOKEN` | пусто | токен агента CloudPub |
| `CLOUDPUB_HTTP` | `oxygen:8080` | что публикует туннель, через запятую |
| `OXYGEN_TRUST_PROXY` | `0` (в `.env.example`: `1`) | адрес зрителя — из `X-Forwarded-For` / `X-Real-IP` прокси во внутренней сети |
| `OXYGEN_VIEW_BIND` / `OXYGEN_VIEW_PORT` | `0.0.0.0` / `80` (в `.env.example`: `127.0.0.1` / `8090`) | где слушать просмотр на хосте |
| `OXYGEN_CONTROL_BIND` / `OXYGEN_CONTROL_PORT` | `127.0.0.1` / `8081` | где слушать управление на хосте |
| `OXYGEN_ARGS` | `--resume --autosave 10` | аргументы сервера (ниже) |
| `JAVA_OPTS` | `-XX:MaxRAMPercentage=75` | параметры JVM |

Аргументы сервера — те же, что у `sct.Main` (`--preset`, `--set имя=значение`, `--seed`, `--w`, `--h`,
`--bots`), плюс:

| Аргумент | Смысл |
|---|---|
| `--resume` | при старте продолжить с `autosave.oxw`, если он есть |
| `--autosave N` | сохранять мир в `autosave.oxw` каждые N минут и при остановке контейнера |
| `--load файл.oxw` | стартовать с сохраненного мира: путь или имя файла в `saved worlds` (важнее `--resume`) |
| `--settings файл.properties` | стартовать с настроек диалога «Новый мир» (тоже имя в `saved worlds`) |
| `--brain-limit N` | как часто один зритель может запросить мозг существа, с (0 — без ограничения) |
| `--trust-proxy` | то же, что `OXYGEN_TRUST_PROXY=1` |
| `--view-rps N`, `--view-burst N` | запросов в секунду с адреса на порту просмотра и допустимый всплеск (0 — без ограничения) |
| `--streams-per-ip N`, `--max-streams N` | потоков кадров с одного адреса и всего |
| `--frame-ms N` | как часто обновляется кадр у зрителей, мс (не меньше 200); меняется и на порту управления |
| `--stats-every N` | точка истории графиков и сверка журнала энергии — раз в N шагов (по умолчанию 10; в окне — каждый шаг). Расхождение баланса копится и между сверками |
| `--record режим_фон[,…]` | видео «последний час» этих видов (ниже); пусто — без записи |
| `--record-ms N`, `--record-minutes N`, `--record-fps N`, `--record-crf N` | кадр раз в N мс (1000), окно (60 мин), скорость просмотра (30 кадров/с), качество H.264 (28; больше — меньше файл) |
| `--record-steps N`, `--record-window-steps W` | вместо времени — кадр ровно на каждом N-м шаге попытки, окно — последние W шагов (по умолчанию 3600 кадров = 3600·N шагов). `--record-ms` и `--record-minutes` тогда не действуют |
| `--kin-every N` | пересчет кланов по геному (режим Kin, счетчик кланов) — раз в N шагов (по умолчанию 500; в окне — 50). Новорожденный до пересчета — в клане родителя |
| `--view-port`, `--control-port` | порты внутри контейнера; `--control-port 0` — без управления вовсе |
| `--token T` | токен вместо `OXYGEN_CONTROL_TOKEN` |

Пример — смешанный мир: `OXYGEN_ARGS=--resume --autosave 10 --set starting_plant_count=1500`.

## Новый мир

- **Веб** (порт управления, вкладка *New world…*) — то же, что диалог New world в программе:
  - *World & species* — размер, зерно, популяции (имя, тело, мозг, численность, цвет; добавить и убрать)
    и таблица взаимодействий: КПД еды, обмен энергии, передача энергии, цепочки, «семечко убивает»;
  - *Oxygen bots* — все параметры `Constant` с поиском и галочки действий каждой популяции ботов;
  - *Plants (biosim)* — набор biosim (*Apply preset*), параметры и действия каждой популяции растений;
  - *Neuro* — параметры сети популяций с мозгом `neuro`; датчики — галочками (снятая галочка пишется в `sensors_off`);
  - *.properties* — те же настройки текстом, можно править и применить.

  Внизу: *Defaults* (настройки запуска сервера), *Current world* (идущего мира), загрузка и сохранение
  `.properties` на сервере или на своем компьютере, *Create*. Параметры, отличающиеся от значений
  по умолчанию, подсвечены; неверные значения — красным, и мир с ними не создается. Перед созданием
  сервер проверяет настройки так же, как диалог, и переспрашивает при предупреждении. Вкладку можно
  открыть по адресу: `http://localhost:8081/#p_new/t_plants`.
- **Пульт с рабочего компьютера** — привычный диалог New world со всеми вкладками,
  только «Create» создает мир на сервере:

  ```bash
  javac -encoding UTF-8 -d out src/sct/*.java src/sct/plants/*.java src/sct/neuro/*.java
  java -cp out sct.RemoteControl http://localhost:8081 <токен>     # через SSH-туннель
  ```

  В пульте также пауза, шаг, скорость, Again и сохранение мира на сервере.

## Файлы

Сохранения, настройки и `autosave.oxw` — в томе `worlds` (`/data/saved worlds` в контейнере).
Порт управления показывает их списком: загрузить, скачать, удалить. Перенести файл вручную:

```bash
docker compose cp "./saved worlds/my.oxw" "oxygen:/data/saved worlds/"
```

## HTTP API

Просмотр и управление: `GET /stream?mode=&bg=&scale=&bots=` (поток кадров), `GET /frame.png?mode=&bg=&scale=&bots=`, `GET /api/status`,
`GET /api/history?group=&n=`, `GET /api/history.csv`.

Каким адресом сервер считает зрителя: `GET /api/whoami`.

Мозг существа: `GET /api/brain?x=&y=` — JSON (`mode`: `bot_genome`, `plant_new`, `plant_old`,
`neuro`, `none`); зрителю при превышении лимита — `429` с `Retry-After`.

Редактор настроек: `GET /api/schema` (тела, мозги, действия, датчики, типы и значения параметров,
наборы biosim), `GET /api/settings.json[?from=startup]`, `POST /api/settings/parse` (`.properties` → JSON).

Кадр отдает заголовки `X-Frame-Step`, `X-Frame-Time`, `X-Frame-Period`, `X-Next-Frame` (мс до
следующего кадра) и `ETag`; с `If-None-Match` уже показанного кадра — `304`.

Видео: `GET /video` — настройки записи и виды (`views`: `url`, `frames`, `dropped`, `state`),
`GET /video/<вид>/index.m3u8`, `GET /video/<вид>/seg_NNNNN.ts`; то же — `recording` в `/api/status`.

Только управление (POST — с заголовком `X-Oxygen: 1`): `POST /api/pause|resume|step|again`, `POST /api/frame?ms=`, `POST /api/brain-limit?sec=`, `POST /api/view-limit?rps=&burst=`,
`POST /api/speed?level=0..6` или `?delta=±1`, `GET /api/settings`, `POST /api/world/new[?force=1]`
(тело — `.properties`), `GET /api/files`, `POST /api/save?name=` (`.oxw` — мир, `.properties` — тело
запроса), `POST /api/load?name=`, `GET /api/download?name=`, `POST /api/delete?name=`.
