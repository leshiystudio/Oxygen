# План: общий мир для трёх видов

Ветка: `feature/multispecies`. Статус: план, код не начат.

## Цель

Один мир, в котором живут три вида существ:

| Вид | Откуда | «Мозг» | Тело |
|---|---|---|---|
| **Бот Oxygen** | текущий `Bot` | геном команд (`update_commands`) | тело Oxygen: газы, органика, цепочки, королевы |
| **Растение** | модель biosim | геном 32×23 (`think_new`) | ростки, `ROOT` / `LEAF` / `TRANS`, трупы, почва |
| **Нейро-бот** | новый | нейросеть (нейроэволюция) | **то же тело, что у бота Oxygen** |

Главные требования:

1. **Правила бота Oxygen не меняются.** Мир, где живут только боты Oxygen, после всех
   переделок даёт **шаг в шаг тот же результат** при том же зерне. Это проверяется
   эталонным тестом (этап 0).
2. **Правила растений — как в biosim.** Переносятся дословно, с целочисленной энергией
   и округлениями biosim.
3. **Общее переиспользуется:** мир-тор, сетка, поток симуляции, отрисовка, панель,
   инструменты, графики, журнал баланса, сохранение, наборы параметров, кланы.
4. **Взаимодействие видов задаётся параметрами**: кто кого видит, ест, кому передаёт
   энергию. Набор действий нейро-бота тоже настраивается.

## Принятые решения

| Вопрос | Решение | Отвергнуто |
|---|---|---|
| Как сосуществуют виды | **Общий мир.** «Режим» — это какие виды заселены при старте; можно запустить один вид | Отдельные миры: виды нельзя столкнуть |
| Среда | **Общая органика**: мёртвое растение кормит ботов-переработчиков и наоборот. Энергия почвы — отдельный слой, только для растений. Газы действуют только на ботов | Свои слои у каждого вида; полная интеграция (растения дышат газами) меняет правила biosim |
| Нейросеть | **Нейроэволюция**: веса наследуются с мутацией, при жизни сеть не учится | Обучение при жизни — позже, отдельным этапом |
| Порядок | Каркас → **растения** → нейро-боты | Нейро раньше растений |
| Что видит бот Oxygen | **Новые коды `see()`**: 7 — растение, 8 — нейро-бот. В мире только из ботов Oxygen они не возникают | Показывать другие виды как «чужого» (4) |
| Еда между видами | **Таблица параметров** (см. ниже). По умолчанию разрешено всё: боты едят растения, растения едят ботов, боты и нейро-боты едят друг друга | Жёстко прописанные правила |
| Действия нейро-бота | **Параметр**: список включённых действий. По умолчанию все действия тела | Урезанный фиксированный набор |
| Энергия растений | **Целые внутри растений**, как в biosim. Числа переводятся на границе видов (еда, органика). Журнал баланса общий, в `double` | Перевести растения на `double` |

## Целевые разделы приложения

Существующие файлы остаются на своих местах в пакете `sct`, ничего не переименовывается.
Новый код — в отдельных пакетах, чтобы не путаться.

```
sct/                      — как сейчас: Bot, WorldBio, Constant, PixelRenderer, панель, ...
  ядро мира (общее):
    BotSuper              — общая база всех существ (сейчас заглушка; см. раздел 1)
    Species               — реестр видов: имя, цвет, создание, параметры
    Interaction           — таблица взаимодействий видов
    WorldBio              — мир: сетка, слои, шаг, поток, блокировка (уже есть)
    Ledger, History, KinClans, WorldIO, Presets, Tools — уже есть, обобщаются
sct/plants/               — растения biosim: Plant, PlantBrain, PlantConfig, почва, трупы
sct/neuro/                — нейро-бот: NeuroBot, Network, Sensors, NeuroConfig
test/sct/                 — SelfTest + эталонный тест (этап 0)
```

### 1. Ядро мира: сетка и общая база существ

Сейчас сетка — `Bot[][] Map`, и `Bot` обращается к соседям напрямую
(`map[x][y].state`, `.genom_array`, `.chain` — около 40 мест).

- **`BotSuper` становится общей базой всех существ.** Заглушка остаётся на своём месте и
  получает своё назначение: позиция, `killed`, вид (`species`) и общие операции:
  - `double energy_value()` — сколько энергии достанется съевшему;
  - `void eaten_by(BotSuper eater, double efficiency)` — смерть от поедания по правилам
    своего вида (у бота — органика, у растения — труп и отмирание ветки);
  - `boolean blocks()` — занимает ли клетку;
  - `String describe()` — для панели и инструмента Info.
- **Сетка становится общей:** `BotSuper[][]`. В `Bot` прямые обращения заменяются
  двумя помощниками:
  - `occupant(pos)` — любое существо в клетке;
  - `bot_at(pos)` — бот (Oxygen или нейро), иначе `null`.

  Где бот взаимодействует с другим существом, явно решается, что делать с чужим видом
  (раздел 2). В мире только из ботов Oxygen ветка «другой вид» не выполняется никогда —
  поэтому эталонный тест проходит.
- `IBot` не трогается.

### 2. Взаимодействие видов (`Interaction`)

Таблица «кто → кого» из параметров. Задаётся в `Constant` и через `--set`, пример:
`--set eat_bot_plant=0.8`.

| Действие | Бот → растение | Растение → бот | Бот ↔ нейро-бот | Значение по умолчанию |
|---|---|---|---|---|
| есть (КПД 0…1, 0 — нельзя) | атака бота | росток ест бота | атака | 1.0 |
| видеть как отдельный вид | `see()` = 7 / 8 | проверка «чужой» | `see()` = 8 / код бота | да |
| передавать энергию (`give`, «поровну») | — | — | да / нет | нет между видами |
| цепочки и королевы | — | — | да / нет | только внутри вида |
| семечко убивает при столкновении | да / нет | — | да | да, как сейчас |
| считать соседом при тесноте (`bot_count`) | да / нет | — | да | **уточнить** (вопрос 1) |

Правило, которое не настраивается: существо другого вида **всегда «чужое»** для проверок
«свой/чужой». Геномы разных видов несравнимы.

Особенность biosim: росток ест ростки и трупы, корень — только трупы. Поэтому «растение
ест бота» означает «росток ест бота». Корень ботов не трогает, если явно не разрешить.

### 3. Среда (слои карты)

| Слой | Кто пишет | Кто читает | Сейчас |
|---|---|---|---|
| кислород, CO₂ | боты (Oxygen и нейро) | боты | есть |
| **органика** (общая) | смерть ботов, трупы растений | переработка ботами, минерализация в почву | есть (`org_map`) |
| **энергия почвы** | минерализация, излишек растений, поедание | растения (`ROOT`/`LEAF`/`TRANS`, токсичность) | новый слой |
| минералы, высоты | — | отрисовка | есть |

- Органика хранится в `double`. Растения работают с ней по формулам biosim
  (целочисленные доли через `floor`): правило не меняется, меняется только тип хранения.
- Токсичность почвы действует только на растения. Газы не действуют на растения.

### 4. Растения (`sct/plants`) — этап 3

Переносятся из `engine.py` в Java-классы:

- `Plant` (наследник `BotSuper`) — одна клетка дерева или росток. Поля — строка `S` из biosim:
  тип, энергия (`int`), здоровье, возраст, направления, энергия в пути, маска получателей,
  родитель.
- `PlantBrain` — `think_new` (проверки, действия, размножение по генам).
  `think_old` — по желанию, позже.
- Тело (`body_step`): забор из почвы, фотосинтез листа, проводник, корень, передача энергии
  по маске, отмирание ветки.
- Трупы `IDEAD`: занимают клетку и отдают энергию в общую органику (`corpse_step`).
- `mineralize`: органика → энергия почвы, вымывание.
- `PlantConfig` — около 70 полей из `SimConfig` biosim с теми же именами. Наборы
  `original` / `balanced` из `presets.py` переносятся в `Presets`.

**Проверка:** в мире только из растений метрики совпадают с biosim статистически (число
клеток по типам, энергия почвы, кланы) на одинаковых настройках. Шаг в шаг не совпадут:
у Java и numpy разные генераторы случайных чисел.

### 5. Нейро-бот (`sct/neuro`) — этап 5

- `NeuroBot extends Bot`: **то же тело**, другой мозг. Переопределяется только
  `update_commands` — выбор действия.
- Чтобы мозг мог вызывать действия, встроенные сейчас прямо в `switch` команд (фотосинтез,
  ход, атака…), они выносятся из `update_commands` в методы `Bot` **без изменения
  поведения** (этап 2, проверяется эталонным тестом).
- **Входы сети (датчики)**: энергия, возраст, кислород, CO₂, органика под собой и
  впереди, результат `see()` для трёх направлений (one-hot по 9 кодам), число соседей,
  связей, статус королевы, есть ли приказ.
- **Выходы**: выбор действия (argmax среди включённых), направление, параметр (количество,
  тип потомка).
- **Сеть**: перцептрон `входы → 16 → выходы`, `tanh`. Веса — `float[]`, при рождении
  копируются с мутацией (шанс и σ — параметры).
- **Действия — параметр** `neuro_actions`: `move, attack, photo, recycle, divide, seed,
  give, share, chain, queen`. По умолчанию все.
- **Кланы**: «свой/чужой» по расстоянию между весами с порогом (параметр). `KinClans`
  получает метрику расстояния от вида.
- Цена: около 1 тыс. умножений на бота за ход, на 20 тыс. ботов — порядка 5–10 мс.

### 6. Интерфейс

- **Новый мир**: диалог «сколько каждого вида» (по умолчанию — только боты Oxygen, как сейчас).
- **Режимы отрисовки**:
  - общие: вид, энергия, кланы по геному;
  - режимы вида: королевы и цепочки — для ботов, типы клеток и энергия в пути — для растений.
- **Фон**: добавляется «энергия почвы».
- **Инструменты ПКМ** работают с любым существом. Окно генома показывает:
  - у ботов — команды;
  - у растений — сетку 32×23 с расшифровкой команд biosim;
  - у нейро-ботов — веса тепловой картой.
- **Графики**: численность и энергия по видам, причины смерти по видам.

### 7. Журнал баланса, история, сохранение

- **Журнал**: полная энергия = боты (энергия + тела) + растения (энергия + энергия в пути)
  + энергия почвы + органика. Статьи прихода и расхода добавляются по видам:
  - растения: солнце, перевод здоровья в энергию, плата за ход, штраф, цена рождения,
    вымывание почвы;
  - между видами: КПД еды меньше 1 — остаток уходит в органику, а не пропадает.
- **История**: колонки по видам.
- **Сохранение**: версия файла 2 с разделами по видам; файлы версии 1 загружаются как мир
  из ботов Oxygen.

## Этапы

| № | Этап | Что проверяем | Объём (оценка) |
|---|---|---|---|
| 0 | **Эталонный тест**: хеш состояния мира после 500 шагов для 3 зёрен, записанный на текущем `main` | тест проходит до и после каждой правки | ~60 строк |
| 1 | Ядро: `BotSuper` — общая база, общая сетка, `Species`, `Interaction`; `Bot` через `occupant`/`bot_at` | эталонный тест, SelfTest | ~300 изменённых, ~200 новых |
| 2 | Действия тела вынесены из `update_commands` в методы | эталонный тест | ~200 перенесённых |
| 3 | Растения: перенос biosim, слой почвы, трупы, `PlantConfig`, наборы | мир из одних растений ≈ biosim; баланс энергии | ~1500 новых |
| 4 | Смешанный мир: таблица взаимодействий, коды `see()` 7/8, панель, графики по видам | баланс энергии в смешанном мире; эталонный тест | ~400 |
| 5 | Нейро-бот: сеть, датчики, действия по параметру, мутация, кланы по весам | эталонный тест; нейро-боты выживают и эволюционируют | ~700 |
| 6 | Оптимизация смешанного мира по замерам: растения на массивах (если объекты медленные), параллельные слои среды | `Bench` | по замерам |

Каждый этап — отдельные коммиты в `feature/multispecies`. После этапов 1, 3 и 5 — смотр вместе с вами.

## Риски

- **Тихо поменять правила Oxygen** при переделке сетки — закрывается эталонным тестом (этап 0)
  до любой правки.
- **Скорость растений на объектах Java.** biosim держит клетки в массивах. Начинаем с
  объектов ради единого взаимодействия; если `Bench` покажет проблему — этап 6 (массивы
  внутри `sct.plants`, наружу тот же `BotSuper`).
- **Разные масштабы энергии.** Старт растения 300, предел 2000; у бота старт 1000, потолок
  1000. Поедание переводит 1:1 с КПД из таблицы — возможно, понадобится коэффициент обмена
  (вопрос 2).

## Открытые вопросы

1. **Теснота.** Бот считает соседей (`bot_count`) для расхода кислорода и фотосинтеза.
   Учитывать ли в этом подсчёте растения и нейро-ботов? Предлагаю «да» (теснота
   физическая); в мире из одних ботов Oxygen это ничего не меняет.
2. **Обмен энергии между видами.** Переводить энергию 1:1 или ввести коэффициент
   «энергия растения → энергия бота»?
3. **`think_old` растений** — переносить сразу или только `think_new`?
4. **Размер мира и стартовые численности по умолчанию** для смешанного мира — взять 400×400
   и поровну, или задавать в диалоге «Новый мир»?
