# План: общий мир для трёх видов

Ветка: `feature/multispecies`. Статус: этап 0 готов (`test/sct/GoldenTest.java`), дальше этап 1.

## Цель

Один мир, в котором живут существа с разными **телами** и **мозгами**. Тело задаёт, что
существо умеет (действия) и как устроено (энергия, смерть, среда). Мозг — алгоритм выбора
действий. Любой мозг подключается к любому телу, если умеет работать с его действиями:

| Тело \ мозг | Геном команд | `think_new` / `think_old` | Нейросеть | Свой алгоритм |
|---|---|---|---|---|
| **Бот Oxygen** — газы, органика, цепочки, королевы | **Bot** (текущий) | — | **NeuroBot** | да |
| **Растение biosim** — ростки, `ROOT`/`LEAF`/`TRANS`, трупы, почва | — | **Plant** | **NeuroPlant** | да |

Мир — список **популяций**. Популяция = тело + мозг + настройки + набор включённых действий.
Две популяции нейро-ботов с разными сетями и действиями («хищники», «травоядные») — просто
две строки в списке, каждая со своим цветом.

Главные требования:

1. **Правила бота Oxygen не меняются.** Мир, где живут только боты Oxygen, после всех
   переделок даёт **шаг в шаг тот же результат** при том же зерне. Это проверяется
   эталонным тестом (этап 0).
2. **Правила растений — как в biosim.** Переносятся дословно, с целочисленной энергией
   и округлениями biosim.
3. **Общее переиспользуется:** мир-тор, сетка, поток симуляции, отрисовка, панель,
   инструменты, графики, журнал баланса, сохранение, наборы параметров, кланы.
4. **Всё, что касается баланса, — параметры**: взаимодействие видов, коэффициенты обмена
   энергии, мозги, сеть нейро-бота. Задаются в диалоге «Новый мир» со значениями по умолчанию.

## Принятые решения

| Вопрос | Решение | Отвергнуто |
|---|---|---|
| Как сосуществуют виды | **Общий мир.** «Режим» — какие виды заселены при старте; можно запустить один вид | Отдельные миры |
| Общий контракт существа | **Интерфейс `IBot`** — общие методы всех видов; **`BotSuper`** — абстрактная база с общими полями. `Bot` и `Plant` наследуют `BotSuper`, `NeuroBot` наследует `Bot` | Только базовый класс без интерфейса |
| Среда | **Общая органика**. Энергия почвы — отдельный слой, только для растений. Газы действуют только на ботов | Свои слои у каждого вида; растения дышат газами |
| Мозг | **Модули**: у растений `think_new` и `think_old` на выбор, у ботов — геном или нейросеть | Один мозг, вшитый в вид |
| Нейросеть | **Нейроэволюция**, все параметры сети настраиваются (см. раздел 5) | Обучение при жизни — позже |
| Порядок | Каркас → **растения** → нейро-боты | Нейро раньше растений |
| Что видит бот Oxygen | **Новые коды `see()`**: 7 — растение, 8 — нейро-бот | Другие виды как «чужой» (4) |
| Еда между видами | **Таблица параметров**, по умолчанию разрешено всё | Жёсткие правила |
| Обмен энергии между видами | **Коэффициент** на каждую пару видов, для регулировки баланса | 1:1 |
| Теснота (`bot_count`) | **Считаются все существа** (теснота физическая); в мире из одних ботов Oxygen ничего не меняется | Только боты |
| Энергия растений | **Целые внутри растений**; перевод на границе видов; журнал общий в `double` | Растения на `double` |
| Параметры нового мира | **Диалог «Новый мир»** с вкладками и значениями по умолчанию | Только аргументы командной строки |
| Разновидности | **Популяции**: любое число сочетаний «тело + мозг + настройки» в одном мире | Один набор настроек на вид |
| Действия | **Модули** (`Action`): имя, категория, параметры, код. Включаются галочками у каждой популяции | Действия, вшитые в `switch` |
| Свои алгоритмы | **Мозг — обычный Java-класс** (`Brain`), пишется на параметрах объекта и мира и вызывает действия по имени; после сборки появляется в меню | Подгрузка скриптов без перекомпиляции — отложено |
| Выключенное действие в геноме | Команда **выполняется без эффекта**: указатель сдвигается как обычно, ход заканчивается так же. Когда включено всё, правила прежние | Команда становится «прыжком» — меняет поток генома |

## Целевые разделы приложения

Существующие файлы остаются на своих местах в пакете `sct`, ничего не переименовывается.
Новый код — в отдельных пакетах.

```
sct/                      — как сейчас: Bot, WorldBio, Constant, PixelRenderer, панель, ...
  контракт и ядро (общее):
    IBot                  — интерфейс существа (сейчас заглушка с двумя методами — они остаются)
    BotSuper              — абстрактная база: позиция, вид, killed (сейчас заглушка)
    Species               — реестр видов: имя, цвет, создание, параметры
    Interaction           — таблица взаимодействий и коэффициентов обмена
    WorldBio              — мир: сетка, слои, шаг, поток, блокировка (уже есть)
    Ledger, History, KinClans, WorldIO, Presets, Tools — уже есть, обобщаются
  интерфейс:
    NewWorldDialog        — диалог «Новый мир» с вкладками (раздел 6)
    ParamForm             — форма параметров, собирается из полей класса настроек
    Action, Brain, Sensors — контракты действий, мозгов и датчиков (раздел 8)
sct/actions/              — действия тела бота Oxygen, вынесенные из update_commands
sct/plants/               — растения: Plant, PlantBrain (ThinkNew, ThinkOld), PlantConfig, действия растений, почва, трупы
sct/neuro/                — нейросеть как мозг для любого тела: Network, NeuroBrain, NeuroConfig; NeuroBot, NeuroPlant
sct/brains/               — свои алгоритмы (примеры: «простой фотосинтетик», «хищник»)
test/sct/                 — SelfTest + эталонный тест (этап 0)
```

### 1. Контракт существа: `IBot` и `BotSuper`

```
          IBot (интерфейс: что умеет любое существо)
            ▲
        BotSuper (абстрактная база: общие поля и реализации по умолчанию)
         ▲                ▲
        Bot             Plant
         ▲
      NeuroBot
```

**`IBot`** — общие методы. Два существующих метода остаются как есть, добавляются остальные:

```java
public interface IBot {
	int Update(ListIterator<IBot> iterator);           //ход существа (уже есть)
	void update_commands(ListIterator<IBot> iterator); //мозг (уже есть)
	Species species();
	int xpos(); int ypos();
	boolean alive();
	double energy_value();                             //сколько энергии достанется съевшему
	void eaten_by(IBot eater, double efficiency);      //смерть от поедания по правилам своего вида
	void die(int cause);                               //смерть по причине (Ledger.DIE_*)
	boolean same_kin(IBot other);                      //«свой/чужой»; другой вид — всегда чужой
	int color(int draw_mode);                          //цвет для отрисовки
	String describe();                                 //для панели и инструмента Info
	void save(DataOutputStream out, Map<IBot, Integer> ids) throws IOException;
}
```

- Сигнатура `Update(ListIterator<IBot>)` уже совпадает с целью: список мира становится
  `ArrayList<IBot>`, и у `Bot` меняется только тип итератора (`ListIterator<Bot>` →
  `ListIterator<IBot>`).
- **`BotSuper`** — `abstract class BotSuper implements IBot`: позиция, `killed`, вид,
  реализации по умолчанию. Пустой `Draw(Graphics, …)` остаётся.
- **Сетка общая:** `IBot[][]`. В `Bot` прямые обращения к соседям (около 40 мест)
  заменяются двумя помощниками:
  - `occupant(pos)` — любое существо в клетке;
  - `bot_at(pos)` — бот (Oxygen или нейро), иначе `null`.

  Где бот взаимодействует с другим видом, решает таблица из раздела 2. В мире только из
  ботов Oxygen ветка «другой вид» не выполняется — эталонный тест проходит.

### 2. Взаимодействие видов (`Interaction`)

Таблица «кто → кого», каждая клетка — параметр. Задаётся во вкладке «Мир и виды» диалога
и через `--set`.

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `eat[A][B]` | может ли A есть B, КПД 0…1 (0 — нельзя; остаток уходит в органику) | 1.0 для всех пар |
| `exchange[A][B]` | коэффициент перевода энергии B в энергию A при поедании | 1.0 — подбирается для баланса |
| `see_species` | видит ли бот другие виды отдельными кодами `see()` (7 растение, 8 нейро-бот) | да |
| `share[A][B]` | передача энергии (`give`, «поровну») между видами | нет |
| `chain[A][B]` | цепочки и королевы между видами | только внутри вида |
| `seed_kills[A][B]` | семечко A убивает существо B при столкновении | да, как сейчас |

- Теснота (`bot_count`) считает все живые существа.
- Существо другого вида **всегда «чужое»**: геномы разных видов несравнимы.
- Особенность biosim: росток ест ростки и трупы, корень — только трупы. Поэтому «растение
  ест бота» означает «росток ест бота». Корень ботов не трогает, если явно не разрешить
  (`eat[root][bot]`).

### 3. Среда (слои карты)

| Слой | Кто пишет | Кто читает | Сейчас |
|---|---|---|---|
| кислород, CO₂ | боты (Oxygen и нейро) | боты | есть |
| **органика** (общая) | смерть ботов, трупы растений, остаток от еды | переработка ботами, минерализация в почву | есть (`org_map`) |
| **энергия почвы** | минерализация, излишек растений | растения (забор, токсичность) | новый слой |
| минералы, высоты | — | отрисовка | есть |

- Органика хранится в `double`. Растения работают с ней по формулам biosim (`floor` для
  целых долей): правило не меняется, меняется только тип хранения.
- Токсичность почвы действует только на растения, газы — только на ботов.

### 4. Растения (`sct/plants`) — этап 3

- `Plant extends BotSuper` — клетка дерева или росток. Поля — строка `S` из biosim: тип,
  энергия (`int`), здоровье, возраст, направления, энергия в пути, маска получателей, родитель.
- **Мозг — модуль** `PlantBrain` с двумя реализациями: `ThinkNew` и `ThinkOld`.
  Выбирается во вкладке растений.
- Тело (`body_step`): забор из почвы, фотосинтез листа, проводник, корень, передача энергии
  по маске, отмирание ветки.
- Трупы `IDEAD`: занимают клетку и отдают энергию в общую органику (`corpse_step`).
- `mineralize`: органика → энергия почвы, вымывание.
- `PlantConfig` — около 70 полей из `SimConfig` biosim с теми же именами. Наборы
  `original` / `balanced` из `presets.py` переносятся.

**Проверка:** в мире только из растений метрики совпадают с biosim статистически (число
клеток по типам, энергия почвы, кланы) при одинаковых настройках.

### 5. Нейро-бот (`sct/neuro`) — этап 5

- `NeuroBot extends Bot`: **то же тело**, другой мозг. Переопределяется только
  `update_commands`.
- Чтобы мозг мог вызывать действия, встроенные сейчас в `switch` команд, они выносятся
  в методы `Bot` **без изменения поведения** (этап 2, проверяется эталонным тестом).

**Параметры (`NeuroConfig`, вкладка «Нейро»):**

| Группа | Параметры |
|---|---|
| Сеть | число скрытых слоёв и нейронов в каждом; функция активации (`tanh`, `relu`, `sigmoid`); память — повторная подача прошлых выходов (вкл/выкл, размер) |
| Входы (датчики) | включение по отдельности: энергия, возраст, кислород, CO₂, органика под собой и впереди, `see()` по направлениям (сколько направлений), соседи, связи, статус королевы, приказ, позиция |
| Выходы (действия) | включение по отдельности: ход, атака, фотосинтез, переработка, деление, семечко, передача энергии, цепочки, королевы |
| Выбор действия | argmax или случайный выбор по весам выходов (softmax с температурой) |
| Наследование | шанс мутации, σ мутации, доля мутирующих весов, начальная инициализация (случайная / нулевая) |
| Кланы | порог «свой/чужой» по расстоянию между весами |

- Цена: около 1 тыс. умножений на бота за ход для сети `входы → 16 → выходы`; на 20 тыс.
  ботов — порядка 5–10 мс. Глубокие сети заметно дороже — это будет видно в `ms/step`.

### 6. Интерфейс

**Диалог «Новый мир»** — все значения уже проставлены по умолчанию, можно сразу нажать «Создать»:

| Вкладка | Что задаётся |
|---|---|
| **Мир и виды** | размер мира, зерно, стартовая численность каждого вида (0 — вида нет), таблица взаимодействий и коэффициентов обмена |
| **Боты Oxygen** | поля `Constant`: газы, возраст, деление, мутации, королевы… |
| **Растения** | поля `PlantConfig`, модуль мозга `think_new` / `think_old`, наборы biosim |
| **Нейро** | поля `NeuroConfig` (раздел 5) |

- Формы собираются автоматически из полей классов настроек (`ParamForm`). У каждого поля
  есть подпись, группа и пределы (аннотация `@Param`). Новый параметр сразу появляется в диалоге.
- Кнопки диалога:
  - «По умолчанию» — сброс значений;
  - «Сохранить набор» / «Загрузить набор» — файл с настройками в `saved worlds`;
  - выбор готового набора (`Presets`).
- Командная строка (`--preset`, `--set`) по-прежнему работает и заполняет диалог.

**Остальное:**

- Режимы отрисовки:
  - общие: вид, энергия, кланы;
  - для ботов: королевы и цепочки;
  - для растений: типы клеток, энергия в пути.
- Фон: добавляется «энергия почвы».
- Инструменты ПКМ работают с любым существом (через `IBot.describe()`). Окно генома показывает:
  - у ботов — команды;
  - у растений — сетку 32×23 с расшифровкой;
  - у нейро-ботов — веса тепловой картой.
- Графики: численность и энергия по видам, причины смерти по видам.

### 7. Журнал баланса, история, сохранение

- **Журнал**: полная энергия = боты (энергия + тела) + растения (энергия + энергия в пути)
  + энергия почвы + органика. Статьи по видам:
  - растения: солнце, перевод здоровья в энергию, плата за ход, штраф, цена рождения,
    вымывание почвы;
  - между видами: при еде с `exchange ≠ 1` разница — отдельная статья, а не утечка.
- **История**: колонки по видам.
- **Сохранение**: версия файла 2 — настройки всех вкладок плюс разделы по видам. Файлы
  версии 1 загружаются как мир из ботов Oxygen.

### 8. Действия и мозги как модули

Это общая основа для всех видов, поэтому закладывается в этапах 1–2, до растений.

```java
public interface Action<B extends IBot> {          //одно действие тела
	String name();                                 //"move", "attack", "photo", ...
	String category();                             //для меню и окна генома
	int args();                                    //сколько параметров читает из генома/сети (направление, количество, тип)
	boolean run(B body, WorldBio w, int[] args);   //выполнить; false — не удалось
}
public interface Brain<B extends IBot> {           //алгоритм выбора действий
	String name();
	void think(B body, WorldBio w, Actions<B> actions);   //actions — только включённые у популяции
	Brain<B> child(B parent, Random rand);         //наследование (с мутацией, если есть)
}
public interface Sensors<B extends IBot> {         //датчики тела: для сети и для своих алгоритмов
	String[] names();
	void read(B body, WorldBio w, float[] out);
}
```

- **Тело регистрирует свои действия и датчики.** Бот Oxygen: ход, атака, фотосинтез,
  переработка, деление, семечко, передача, «поровну», цепочки, королевы. Растение: действия
  `todo_list` biosim и размножение типами клеток.
- **Мозг геномом** (`update_commands`) остаётся как есть: команда вызывает действие по
  номеру через таблицу «команда → действие». Проверки и переходы генома остаются в нём.
- **Нейросеть одна на все тела:** число входов = датчики тела, выходы = включённые действия
  тела и их параметры. Так `NeuroBot` и `NeuroPlant` — одна и та же сеть на разных телах.
- **Свой алгоритм** — класс `implements Brain<Bot>` или `Brain<Plant>`, пишется как сейчас:
  ```java
  if (body.energy < 300 && actions.has("photo")) actions.run("photo");
  else if (sensors.see(FRONT) == ALIEN)          actions.run("attack", FRONT);
  ```
  Регистрируется одной строкой в списке мозгов и появляется в диалоге.
- **Галочки.** В диалоге «Новый мир» у каждой популяции список действий её тела с
  галочками. Выключенное действие не выполняет ни геном, ни сеть, ни свой алгоритм.

| 3 | Растения: перенос biosim, оба модуля мозга, слой почвы, трупы, `PlantConfig`, наборы | мир из одних растений ≈ biosim; баланс энергии | ~1700 новых |
| 4 | Смешанный мир и диалог «Новый мир»: популяции, галочки действий, таблица взаимодействий, коды `see()`, `ParamForm`, графики по видам | баланс энергии в смешанном мире; эталонный тест | ~900 |
| 5 | Нейросеть как мозг: `NeuroBot` и `NeuroPlant`, датчики и действия по параметрам, мутация, кланы по весам, вкладка «Нейро»; пример своего алгоритма | эталонный тест; нейро-популяции выживают и эволюционируют | ~1000 |
| 6 | Оптимизация смешанного мира по замерам: растения на массивах (если объекты медленные), параллельные слои среды | `Bench` | по замерам |

Каждый этап — отдельные коммиты в `feature/multispecies`. После этапов 1, 3 и 5 — смотр вместе с вами.

## Риски

- **Тихо поменять правила Oxygen** при переделке сетки и списка — закрывается эталонным
  тестом (этап 0) до любой правки.
- **Скорость растений на объектах Java.** biosim держит клетки в массивах. Начинаем с
  объектов ради единого контракта `IBot`. Если `Bench` покажет проблему — этап 6.
- **Разные масштабы энергии.** Старт растения 300, предел 2000; у бота старт 1000, потолок
  1000. Регулируется коэффициентами `exchange`.
- **Объём диалога.** Около 150 параметров на трёх вкладках. Автоматическая форма с группами
  и поиском держит это в порядке.

## Открытых вопросов нет

Разновидности нейро-ботов решены популяциями (раздел «Цель»).
